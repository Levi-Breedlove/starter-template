# Security reporting

Send the repository owner a private report with the affected revision, component, observed impact and the smallest safe local demonstration. Use GitHub private vulnerability reporting when the repository offers it. Remove account identifiers, credentials, tokens and customer data from examples and logs.

Use synthetic data for local tests. Preserve the existing client sandbox, trust settings, project permissions and delivery approvals. If a secret may have been exposed, report it privately to its owner and follow the project's credential response procedure.
