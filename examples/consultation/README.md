# Consultation examples

These fictional dialogues illustrate how Codex should lead the workflow. They are not transcripts of executed sessions, accepted project decisions, test results, or AWS deployments. Their application choices belong to the examples; they are not defaults for every project.

- [Greenfield consultation](greenfield.md): a new booking capability, an adaptive interview, requirements analysis, a design recommendation, and a dependency-aware task plan.
- [Brownfield consultation](brownfield.md): an existing retry defect, repository-derived facts, one unresolved product policy, preservation requirements, and a scoped fix plan.

Observe the behavior rather than memorizing the wording. Codex reads known context first, derives technical consequences, recommends an approach, asks a few consequential questions, saves each answer, and performs the route's real reviews. Existing authority carries forward. Unknown decisions and unperformed checks stay visible.

Use [the interview guide](../../guide/06-consultation-interview.md) for the operating detail and [Consult](../../workflows/consult.md) for the procedure. The local tools can scaffold and validate recorded structure; they do not turn these illustrative conversations into live evidence.
