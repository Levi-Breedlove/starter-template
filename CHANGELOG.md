## Upgrading an adopted application

Commit or otherwise preserve existing work under its normal controls. Use a separate checkout of the intended release. Preview the bootstrap against the application with its original adoption mode and `--upgrade`. Review the mappings, package changes and managed instruction block, then repeat the same command with `--apply`. Run the installed `doctor`, review the saved handoff, and reverify affected work before continuing. If local edits conflict with managed bytes, inspect the original and new versions and resolve the conflict deliberately. Keep user-owned records and existing task authority.

Choose a tagged revision after release, and retain the previous package revision for recovery. An application generated from a GitHub template has its own Git history. A later template release does not update that application automatically.
