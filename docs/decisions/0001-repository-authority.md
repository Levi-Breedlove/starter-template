# Decision 0001: Repository authority

**Status:** Implemented organization, extended by the consultant workflow slice.  
**Date:** 2026-11-22.

## Decision

Use a concise root instruction router, canonical work documents and executable local validators. Keep one completion authority in each work's task document. Index facts, questions, phase and evidence without creating competing copies of project decisions.

Separate framework maintenance from adopting application context. Adopt through a deliberate additive package and mapped instruction block; preserve existing architecture, files, IaC ownership and delivery controls. The helper's file checks do not replace semantic review of existing instructions.

Use supported Codex event definitions only where verified, with actual client trust left to the supported interface. Reuse official AWS plugin identities and current guidance. No private skill collection or application architecture is required by the bootstrap.

## Consequences

The system combines readable project contracts with deterministic checks. It still needs model judgment for interviewing, design and implementation, and real observations for native/cloud claims.
