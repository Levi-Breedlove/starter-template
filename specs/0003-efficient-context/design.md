# Design: focused context and measured efficiency

**Contract:** [Requirements](requirements.md).  
**Review route:** Combined quick review under actual delegated repository-maintenance authority.

## DES-001 — One read-only projection

Keep `inspect_work` and the existing audit reports unchanged. A pure context module projects the report into a compact object and text. It budgets individual fields and records, prioritizes issues/blockers and the next action, reduces completed history to counts, and discloses omitted records with canonical references. No serialized record is sliced arbitrarily in place of structure.

Current route and phase guide the proposed next action. At most three eligible tasks expose titles, prerequisites and contract/design/check references. A quick route uses its combined review; planning completion does not become implementation permission. Suggestions remain advisory and do not mutate workflow state.

## DES-002 — Event-specific context

Session start/resume receives the fuller compact packet, capped at 6000 characters. Prompt submission receives a refresh capped at 1200 characters with current problems/action and a stable fingerprint of the full inspection report. The agent reloads when there is no loaded packet or the report changes, while still inspecting changed source and applying user steering.

The handler has no persistence/cache and still performs current inspection. Stop remains warning-only. Native token thresholds are separate from character limits, and actual selected-client loading/trust is not implied by fake-event tests.

## DES-003 — Adoption and operating policy

The installer requires and packages the new runtime module. Source and generated application instructions use compact entry, selective source loading, bounded useful delegation and proportionate verification. They preserve required gates and user authority. The existing evaluation protocol becomes explicitly quality-first, then compares observed effort and cost where available.

## DES-004 — Evaluation and reconciliation

Capture the prior tested renderer before edits and compare identical synthetic reports after implementation. Report payload characters and bytes, not inferred token prices or universal performance. Regression tests cover retained errors, strict caps, omission counts, compatible full inspection, phase-specific next action, read-only behavior and actual packaged CLI/events.

Earlier receipts remain historical observations. Where shared source changes invalidate prior declared inputs, revalidate the applicable earlier contract using the actual new combined run and append new evidence; do not edit old pass receipts to imply they tested new code. Publication compares every current file identity after the branch update.
